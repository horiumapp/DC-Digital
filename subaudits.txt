### 1. CRITICAL — Any SECRETARIO/GESTOR can hijack a professor from another school, then read and write that school's notas/frequencias

Two permissive policies compose into a full cross-tenant escalation chain.

**Step 1** — `d:\DDigital-Cursor\DC-Digital\supabase\migrations\20260828000019_align_gestor_writes_and_fechamento_reopen.sql:41-44`

```sql
DROP POLICY IF EXISTS "admin_insert_professor_alocacoes" ON public.professor_alocacoes;
CREATE POLICY "admin_insert_professor_alocacoes" ON public.professor_alocacoes
  FOR INSERT
  WITH CHECK (p_escola_permitida(professor_alocacoes.escola_id));
```

Nothing checks who `professor_id` is, nor whether that professor already belongs to another school. A SECRETARIO of school B passes `p_escola_permitida(B)`, so it can insert an allocation for **any** professor UUID, including professors of school A. (`authenticated` holds INSERT on this table via `20260926000005_audit_bootstrap_grants.sql:7-13`.)

**Step 2** — `d:\DDigital-Cursor\DC-Digital\supabase\migrations\20260707000000_schema.sql:1024-1033` (never superseded — this is still the final `professores` UPDATE policy)

```sql
CREATE POLICY "admin_update_professores" ON public.professores
  FOR UPDATE
  USING (((( SELECT get_user_role() AS get_user_role) = 'ADMIN'::text) OR (is_admin_or_staff() AND (EXISTS ( SELECT 1
   FROM professor_alocacoes pa
  WHERE ((pa.professor_id = professores.id) AND (pa.escola_id = get_user_escola_id())))))))
  WITH CHECK ( ... same ... );
```

After step 1 the EXISTS is satisfied, so the attacker may rewrite that professor's row.

**Step 3** — `d:\DDigital-Cursor\DC-Digital\supabase\migrations\20261013000001_cpf_rate_limit_disciplinas.sql:22-28` explicitly re-grants the two columns that make the hijack possible:

```sql
REVOKE SELECT, UPDATE ON TABLE public.professores FROM PUBLIC, anon, authenticated;
GRANT UPDATE (
  nome, email, telefone, vinculo, status, departamento, disciplinas, usuario_id
) ON TABLE public.professores TO authenticated;
```

**Exploit:** `UPDATE professores SET usuario_id = auth.uid(), email = '<attacker email>' WHERE id = '<professor de outra escola>'`.
Then, because of `professor_tem_acesso_a_turma()` / `professor_tem_acesso_a_turma_disciplina()` (`20260712000002_security_fixes.sql:123-141`, `20260926000001_audit_authorization_integrity.sql:24-32`):

```sql
(p.usuario_id IS NOT NULL AND p.usuario_id = auth.uid())
OR (p.usuario_id IS NULL AND p.email = (auth.jwt() ->> 'email'))
```

the attacker is now that professor: `auth_select_notas` / `auth_select_frequencias` / `auth_select_alunos` grant read, and `professor_pode_inserir_nota` / `professor_pode_editar_frequencia` / `professor_pode_inserir_frequencia` (`20260918000026...:208-359`) grant **write** on the other school's grades and attendance, plus full aluno PII (CPF, endereço, telefone, responsável) via `auth_select_alunos`'s PROFESSOR branch.

**Minimal fix:** in the `professor_alocacoes` write policies restrict target professors to ones already allocated in that school or unallocated, and revoke `usuario_id`/`email` from the `authenticated` column grant on `professores`, e.g.

```sql

CREATE POLICY "admin_insert_professor_alocacoes" ON public.professor_alocacoes
  FOR INSERT WITH CHECK (
    p_escola_permitida(professor_alocacoes.escola_id)
    AND NOT EXISTS (SELECT 1 FROM public.professor_alocacoes pa
                    WHERE pa.professor_id = professor_alocacoes.professor_id
                      AND pa.escola_id <> professor_alocacoes.escola_id)
  );
REVOKE UPDATE (usuario_id, email) ON TABLE public.professores FROM authenticated;
```

(`usuario_id` should then only be set by `finalize_provisioned_user`, which already does it as SECURITY DEFINER.)

### 2. HIGH — GESTOR_SEMEC gets full write on alunos, turmas, alocações and horários of *every* school

`d:\DDigital-Cursor\DC-Digital\supabase\migrations\20261009000000_gestor_semec.sql:4-23` widened the shared helper:

```sql
CREATE OR REPLACE FUNCTION public.p_escola_permitida(p_escola_id uuid)
...
  SELECT
    (SELECT public.get_user_role()) = 'ADMIN'
    OR public.usuario_tem_escopo_rede()
    OR (
      (SELECT public.get_user_role()) = 'GESTOR_SEMEC'
      AND p_escola_id IS NOT NULL          -- any school, no tenant predicate
    )
```

That helper is the *only* predicate on the write policies created earlier in `d:\DDigital-Cursor\DC-Digital\supabase\migrations\20260828000019_align_gestor_writes_and_fechamento_reopen.sql:7-72`:

```sql
CREATE POLICY "admin_insert_alunos"  ... WITH CHECK (p_escola_permitida(alunos.escola_id));
CREATE POLICY "admin_update_alunos"  ... USING/WITH CHECK (p_escola_permitida(alunos.escola_id));
CREATE POLICY "admin_delete_alunos"  ... USING (p_escola_permitida(alunos.escola_id));
CREATE POLICY "admin_insert_turmas"  ... WITH CHECK (p_escola_permitida(turmas.escola_id));
CREATE POLICY "admin_insert_professor_alocacoes" ... (p_escola_permitida(escola_id));
CREATE POLICY "admin_insert_professor_horarios"  ... (p_escola_permitida(escola_id));
```

The role was introduced as read-only for schools/turmas/professores/alunos ("visão da rede", and deliberately excluded from `usuario_tem_escopo_rede`), and only `escolas`/`professores` got explicit SEMEC write policies. Because the helper now returns `true` for any school, GESTOR_SEMEC also inherits INSERT/UPDATE/DELETE on `alunos`, `turmas`, `professor_alocacoes`, `professor_horarios` network-wide, and via `ON DELETE`/FK rewrites can move students between schools (`alunos.escola_id` is nullable since `20260912000025...:20`). The same widening lets SEMEC rewrite any school's timetable through `replace_professor_horarios` (`20260926000004...:25`, `IF NOT public.p_escola_permitida(p_escola_id)`).

**Minimal fix:** keep `p_escola_permitida` as the *read* helper and give writes their own helper:

```sql
CREATE OR REPLACE FUNCTION public.p_escola_gravavel(p_escola_id uuid) RETURNS boolean
LANGUAGE sql STABLE SECURITY DEFINER SET search_path = public, pg_temp AS $$
  SELECT (SELECT public.get_user_role()) = 'ADMIN'
      OR ((SELECT public.get_user_role()) IN ('GESTOR','SECRETARIO')
          AND p_escola_id IS NOT NULL AND p_escola_id = public.get_user_escola_id());
$$;
```
then `ALTER POLICY` the six write policies to `p_escola_gravavel(...)`.

### 3. MEDIUM — `reject_public_signup` regression: role-less public signup is allowed again

`d:\DDigital-Cursor\DC-Digital\supabase\migrations\20261013000001_cpf_rate_limit_disciplinas.sql:137-152` (final version of the function):

```sql
DECLARE
  cargo text := upper(btrim(coalesce(NEW.raw_app_meta_data->>'role', '')));
```

### 10. LOW — `finalize_provisioned_user` trusts the client-supplied `p_actor` for identity

- Aluno isolation is sound: `aluno_e_o_proprio` / `aluno_tem_acesso_a_turma` (`20260908000021:25-80`) require `usuario_id = auth.uid()`, institutional `<cpf>@aluno.dcdigital.local` identity, or direct id — no policy lets an aluno read another aluno's notas/frequências/atestados.
- Professor writes on notas/frequências/avaliações/conteúdos are disciplina-scoped (`professor_tem_acesso_a_turma_disciplina`) and additionally guarded by `guard_academic_relationships` / `guard_academic_period` / `check_fechamento_transition` triggers, so the older turma-wide predicates in `fechamentos_bimestres` are compensated.
